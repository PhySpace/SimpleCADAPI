# 2.2.6.post1 更新说明

编辑器参数面板的热修复，以及一轮针对 notebook 缓存和 `use` 的速度优化，数据来自桌面六轴机械臂。

## `scad.var(name=..., default=...)` 重新被识别为参数

编辑器只把 `scad.var` 的第二个**位置参数**当作默认值。用关键字写的声明——

```python
J1 = scad.var(name="j1", default=0.0, comment="Joint 1")
```

——会被跳过：没有滑块，也无法写回文件。现在两种写法都能读取，提交数值时也会改写对应的那个参数。

## 缓存运行的代价

| 桌面机械臂 | 之前 | 现在 |
|---|---|---|
| 冷启动 | 80.5 s | 34.6 s |
| 什么都没改 | 23.6 s | 4.0 s |
| 改一个关节角 | 18.2 s | 3.0 s |
| 改一个连杆长度 | 35.1 s | 19 s |
| 磁盘缓存 | 1.7 GB | 96 MB |

- **恢复更便宜。** 恢复出来的形状在第一次被用到时才构建，没有 cell 读取的缓存值不花时间；标签缓存只重建一次，
  不再每个祖先一次。缓存不再存 cell 私有（`_name`）变量的值，并压缩写入的内容；旧条目照样能读。
- **参数按值定键。** 读取某个 `scad.var` 的 cell，不会因为同一个 cell 里的邻居参数变化而重跑。
- **按名字而不是按文件。** `from lib.dims import A` 只依赖 `A` 的定义。
- **`use` 按调用逐个跟踪。** 用字面量路径 `use` 一个 notebook 的 cell 依赖那个 notebook（文本、它导入的模块、
  它再 `use` 的 notebook）：改一个子 notebook 只重跑用它的 cell，不动它的兄弟。编辑器内核也缓存这类 cell。
- **`use` 并行。** cell 即将发出的 `use` 调用交给 worker 进程同时构建（线程没用：OpenCASCADE 不释放解释器锁），
  cell 随后发现已经建好。`SCA_JOBS` 设置数量（默认 4 与核数的较小值；`1` 关闭）。只有省下的时间大于 worker
  启动成本才会启动，并且 notebook 运行期间其状态目录在进程间加锁。
- **编辑器滑块。** 拖动在停顿 250 ms 或松开时才发送，不再逐步发送。
