# 2.2.9 Update Notes

2.2.9 replaces 2.2.8, which has been withdrawn (yanked on PyPI, its GitHub release deleted). 2.2.8 let a `Part` hold several
bodies, and a Part like that could not take part in an assembly. In 2.2.9 a Part holds exactly one solid again, and the
editor keeps what it needed from the change: several solids can sit side by side in a notebook while a model is built.
Everything else in 2.2.8 is in 2.2.9; the 2.2.8 notes describe it.

## Why a Part holds one solid

The editor has to let several solids exist in one notebook with no assembly constraint between them: to pattern a tool and then
cut, there is a moment where more than one tool and the body exist together. In 2.2.8 that was solved inside the Part. But a
Part is the unit an assembly places, mates and gives connectors to, and a Part of several bodies could do none of that:

* connectors on it were refused, so no mate or public connector could reach it;
* `explode_rassembly` raised `TypeError` on any assembly that held one;
* the older scene compiler read the single body of a Part in four places.

The solids side by side are intermediate values of a notebook, not product items. So they are notebook values now, and the
Part is one solid. The full account is in `design-docs/part-holds-one-solid.md`; every commit of the change states its own
reason.

## What changes for you

* **`make_part_rpart(part_id, body, name=None)`** takes one Solid, a `Body` (a solid with a display name, colour and opacity), or
  a list of exactly one piece of a split cut. Several solids raise `ValueError`, which says what to do: one Part per solid in
  an Assembly (identity placements when they only sit together), or union / cut them into one solid first.
* **Removed** (they only existed in the withdrawn 2.2.8): the `bodies=` argument, `Part.multi_body`, `scad.part_shape`,
  `inspect_body_overlaps_rlist`, `BodyOverlap`, `BodyOverlapWarning`, and the part definition profile
  `simplecad-part-definition-3` with `solid_cache.bodies`. A part definition is profile 2 with one solid, as before 2.2.8.
  A model JSON recorded with several solids in one Part is refused on replay, with the same guidance.
* **A part notebook with one open solid** (`kind = "part"`, no cell making the Part) still gets the implicit Part. **With several
  open solids** there is no product: running it raises `SeveralOpenBodiesError`, which names the solids; make the Part from the
  one that is the part (`scad.make_part_rpart(part_id=scad.notebook_id(), body=...)`), or make a Part of each and an Assembly
  of them.
* **The editor** draws such open solids side by side and its header says "N open solids"; `use_as_product` makes the Part
  from the solid you choose. One-body Parts, `Pieces` (the result of a splitting cut), connectors, mates and `explode_rassembly`
  behave as they did.

## Fixed

* On Windows, `sca cell` no longer kills the editor it talks to: the editor's process id is probed without signalling it
  (`os.kill(pid, 0)` on Windows terminates the process).
* Building from source: GCC 14 (`operators_promote.cpp` includes `<algorithm>`), MinGW (`_USE_MATH_DEFINES`, and
  `build_occt.py` picks Ninja when a MinGW `g++` is the compiler), and the macOS wheels are built on `macos-15` (GitHub no
  longer serves `macos-14`; the wheels still target macOS 14.0).
