# 2.2.6.post2 更新说明

SDK 的计算结果没有变化。八个算子搬进了各自所属家族的模块，并且它们所在的 API 参考现在全部由生成器生成。

## 算子放在自己家族的模块里

| 算子 | 现在在 |
|---|---|
| `scale_rsolid`、`transform_rsolid` | `operators/transform.py`（和 `translate_shape`、`rotate_shape` 在一起） |
| `boolean_rsolidlist` | `operators/boolean.py`（和 `union_rsolid`、`cut_rsolid` 在一起） |
| `offset_rsolid`、`draft_rsolid`、`extrude_taper_rsolid`、`extrude_until_rsolid`、`sweep_multisection_rsolid` | `operators/features.py`（和 `extrude_rsolid`、`shell_rsolid`、`sweep_rsolid` 在一起） |

`from simplecadapi import scale_rsolid`（以及其他所有名字）用法不变。原先从它们最初所在的模块
`simplecadapi.operators.deformation`、`draft`、`section_features`、`limited_extrusion` 导入的代码仍然可用，
会得到一条指出新位置的 `DeprecationWarning`；请改为从 `simplecadapi` 导入。

## 每个算子的 API 参考都由生成器生成

文档生成器自己维护一份手写的源文件和公开函数清单，没人把那四个模块加进去。于是上面八个算子的文档是手写的，
生成器每次运行都会把它们删掉，`boolean_rsolidlist` 则根本没有文档。现在 `operators/` 自动发现，包导出的函数就是公开 API，
手写文档里的内容（示例、错误条件、操作如何回放）已经进了 docstring，也就进了生成的文档。
公开算子缺文档、或已提交的文档与生成器输出不一致，测试都会失败。
