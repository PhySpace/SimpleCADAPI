# 2.2.6 更新说明

和 2.2.5 来自同一份实地报告的续篇：agent 在多 notebook 工作区里干活，不用再绕开 CLI
才能继续——它依赖的缓存也重新有了签名验证。

## 不离开 CLI 就能切换 notebook

一个 agent 要同时编辑 `l_link.py`、`l_link_shell.py` 和一个装配体，把编辑器在它们之间
切换的办法只有一个：对着 `/api/workspace/open` 发裸 `curl`——这个端点是它读了安装包里
server 的源码才找到的，因为编辑器开着别的 notebook 时写入会被拒绝，而没有任何命令能切换。
现在：

```bash
sca cell open other.py        # 编辑器切换过去；等 kernel 启动完成
echo '...' | sca cell put 3 --open   # 切换 + 写入一步完成
```

`sca cell open` 会等到切换后的 notebook kernel 就绪（`SCA_EDITOR_OPEN_WAIT` 或
`--wait`，默认 120s），后续写入不会和启动赛跑。对已经打开且就绪的 notebook 再次执行
不会重启 kernel。写入被拒绝时报错会直接给出这条命令，`/api/cells` 也会报告 `kernel`，
让调用方分得清"名字已切换"和"kernel 还在启动"。

## 像命令一样拿视口图

```bash
sca viewport --out /tmp/seen.png     # 路径、age（秒）、大小；复制出来
```

"用户现在看到什么"的图，现在是 `sca viewport` 的输出，而不是一个要 agent 自己知道、
自己读的 `.sca-editor/viewport.png` 文件。age 说明画面有多新鲜；页面从未显示过模型时
没有图。

## 缓存条目重新有了签名验证

notebook 缓存是 marimo 的 `LazyLoader`，默认开着验证：缺 `cryptography` 包时会降级关
闭，每次运行都警告"cache entries are neither signed nor verified"。现在 `cryptography`
作为依赖随包安装，缓存能工作的地方验证就开着。
