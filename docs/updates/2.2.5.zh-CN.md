# 2.2.5 更新说明

来自容器 agent 的实战复盘：编辑器现在按 agent 真实的使用方式工作，并且把发生的事说出来，而不是留下沉默。

## `sca cell` 在容器代理后面也能找到编辑器

以前容器的 `http_proxy` 会吞掉编辑器的健康检查，`sca cell` 在编辑器明明运行时回答"no editor is running"。
现在编辑器的发现记录始终携带回环地址（`--host 0.0.0.0` 也是），检查绕过代理环境，应答不了的服务器记录会带着
路径和 url 报出来，而不是被悄悄跳过。pid 已消失的记录会说"stale record … delete it or restart the editor"。
`sca cell ls`/`get` 降级读文件时会在 stderr 上说明。

## cell 反馈带着整条链

`sca cell put/insert/run` 现在返回 console 输出和这次修改留下的每一个不健康的 cell，写操作导致的 stale 依赖
会被运行而不是晾着。出错 cell 的报告会列出它的上游 cell（先列出同样在报错的），让错误能追溯到根因。重跑超出
调用时长的写操作现在回答"the edit was applied and the rerun is still going; check `sca cell ls`"而不是裸的
socket 错误（`SCA_EDITOR_CALL_TIMEOUT` 可加大等待，默认 300 秒）。

## 按阶段做无头校验

```bash
sca run stage.py --through 3 --no-product    # 只跑前 3 个 cell，不需要产品
sca run stage.py --timeout 600               # 给重 fillet 一个墙上时钟
```

`--through N` 只跑前 N 个 cell（按编辑器的编号方式计）；`--no-product` 运行还没有产品的半成品 notebook；
`--timeout` 让超时的运行失败（默认不限时）。

## 更安静的输出、更短的打印

缓存加载器的降级警告（未签名的条目、以 stub 恢复的值）不再以 WARNING 打印，渲染路径进程级关闭 VTK 的警告
显示——同一进程里你自己代码的 VTK 警告也会被隐藏。真正的失败仍然会大声报出并点名。打印 `BRepInspection`
现在是一行摘要；逐面记录在 `to_dict()` / `.faces` / `.edges`。

## Skill

编辑器运行时，`sca cell` 是修改普通 cell 的唯一方式——直接改文件只在没有编辑器运行时，或用于 `sca cell`
拒绝的 setup / `@app.function` cell。`dof=0` 说明约束系统闭合了，不说明形状是对的（角度约束可能解出镜像
解）：用测量来验证。建模项目按软件工程的方式管理：从第一个文件就用 git，在验证通过的节点提交。
