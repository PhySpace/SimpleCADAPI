# 2.2.6 Update Notes

From the same field report as 2.2.5, the follow-up: an agent working a
multi-notebook workspace no longer has to leave the CLI to keep working — and the
cache it relies on is verified again.

## Switch notebooks without leaving the CLI

An agent editing `l_link.py`, `l_link_shell.py`, and an assembly had exactly one way
to move the editor between them: a raw `curl` to `/api/workspace/open`, an endpoint
found by reading the installed server's source — because a write refuses while
another notebook is open, and no command could switch. Now:

```bash
sca cell open other.py        # the editor switches; waits for the kernel to boot
echo '...' | sca cell put 3 --open   # switch and write in one step
```

`sca cell open` waits until the switched notebook's kernel is up
(`SCA_EDITOR_OPEN_WAIT` or `--wait`, default 120s), so the following write does not
race the boot. Re-asking for the notebook that is already open and ready does not
restart the kernel. A refused write names the command as the remedy, and
`/api/cells` reports `kernel` so a caller can tell a booted notebook from one whose
name has flipped while the kernel still boots.

## See the viewport as a command

```bash
sca viewport --out /tmp/seen.png     # path, age in seconds, size; copied out
```

The image of what the person sees is now `sca viewport`'s answer instead of a
`.sca-editor/viewport.png` file agents had to know about and read by hand. The age
says how fresh the view is; there is no image until the page showed a model at
least once.

## Cache entries are signed and verified again

The notebook cache is marimo's `LazyLoader`, whose verification is on by default:
without the `cryptography` package it degraded to off and every run warned that
cache entries were neither signed nor verified. `cryptography` ships as a
dependency now, so verification stays on everywhere the cache works.
