# 2.2.7b1 更新说明（beta）

几何引擎改为基于 OpenCASCADE 的 C++，随 wheel 一起发布。`pip install simplecadapi` 不再需要
`cadquery-ocp`，机器上也不需要装 OpenCASCADE。模型、图、包和公开 API 的行为不变：此前的整套测试在新引擎上全部通过。

## 预编译包

| 平台 | wheel |
|---|---|
| Linux x86_64（manylinux_2_28） | Python 3.10、3.11、3.12、3.13 |
| Linux aarch64（manylinux_2_28） | Python 3.10、3.11、3.12、3.13 |
| macOS arm64（macOS 14+） | Python 3.10、3.11、3.12、3.13 |
| Windows x86_64 | Python 3.10、3.11、3.12、3.13 |

所有 wheel 链接同一份从源码构建的 OpenCASCADE 7.9.3，所以同一个模型在各平台上算出一样的结果。
macOS Intel、musl Linux、Windows ARM 没有预编译包；这些平台由源码包现场构建，需要 C++20 工具链和 OpenCASCADE >= 7.8。

这是第一个带预编译 wheel 的版本：遇到无法安装或无法导入的平台，请反馈。

## 更快、更小

六轴机械臂（`sandbox-envs/desktop_arm_sources`），同样的源码、同一台机器，Python 运行时：

| | 2.2.6.post2 | 2.2.7b1 |
|---|---|---|
| 冷构建 | 43.8 s | 29.1 s |
| 无改动 | 12.8 s | 6.0 s |
| 改一个关节 | 9.9 s | 6.1 s |
| 冷构建峰值内存（整个进程树） | 2690 MB | 2043 MB |
| `import simplecadapi` | 1.6 s，360 MB | 0.2 s，68 MB |

算出的模型相同（体积相对差 1e-12 量级）。

## 一个包

* 编译模块是 `simplecadapi._cpp`；`simplecadapi.core`、`simplecadapi.operators.*`、`simplecadapi.ql`、
  `simplecadapi.std.*` 等模块保留原有导入路径，作为转发模块存在，每个模块的文档字符串都写明了名字由哪个 C++ 源文件定义。
* 移除的依赖：`cadquery-ocp`、`ocp-gordon`、`py-slvs`。形状的 OpenCASCADE 视图（`shape.wrapped`）现在是模块自带的绑定
  `simplecadapi._cpp.occt`，布局与 OCP 相同。
* `SCA_BACKEND` 已删除：只有一个后端。
* `simplecadapi.inspect.brep` 使用与 `render_screenshot_rpath` 相同的软渲染：不依赖 VTK、GPU 和显示服务（无需 `xvfb`）。`inspect` 额外依赖只剩 `matplotlib`。

## 会把实体切成多段的布尔运算

* 新增 `cut_rsolid_list(base, *tools)`，返回切割产生的每一段：在棒上开通槽得到两段，工具把整个实体包住则得到空列表。
  它记录为 `make_cut_rsolid_list`，可以回放。
* 以前切割把实体分成多段时，`cut_rsolid` 只返回第一段，其余静默丢失（100x20x10 的棒开通槽，体积只剩一半）。
  现在它会报错并指向 `cut_rsolid_list`。工具只与壁面相切时也会留下一块独立的残片，所以依赖"丢掉残片"的脚本需要把工具
  改成不碰壁面，或改用 `cut_rsolid_list`。

## 报错

* 库写出的所有消息都是英文。
* 标签校验、语义查询两类报错和其他算子报错一样完整渲染：发生了什么、可能原因、如何修复。

## Python 3.10 到 3.13

四个版本都已构建并测试。
