# 2.3.0.post1 更新说明

2.3.0.post1 接在 2.3.0 之后。它是下面这个编辑器修复，加上 2.3.0 之后合并到 `dev` 的全部内容（绘图引擎重做、并行构建 wheel）；
几何内核没有改动。

## 编辑器靠它自己的回答被找到

`sca cell` 过去对 `.sca-editor/server.json` 里的 pid 做 `os.kill(pid, 0)`，把"没有这个进程"当成编辑器已死。有独立 pid 命名空间的沙箱
看不到编辑器的进程，而编辑器其实在回答，于是沙箱外启动的编辑器全被判成"stale"，agent 就丢了编辑器
（"editor not reached: stale record ... (pid N is gone)"）。

现在以 `/api/health` 为准，而且它回答的 workspace 必须等于记录所在目录：

| `sca cell` 说 | 含义 |
|---|---|
| `... does not answer` | 那个 url 上没有编辑器；启动一个（pid 已不在只会让这句更具体） |
| `answers for workspace X, not Y` | 那个端口属于另一个项目的编辑器；不会向它发送任何东西 |
| `N editors serve ...` | 有多个编辑器活着；不替你选 |

## 多个编辑器并行

* 每个编辑器有一个实例 id（在 `/api/health` 里）和自己的记录 `.sca-editor/editors/<instance>.json`，原子写入，只由它自己删除。
  `server.json` 已移除；读它的代码改读这个目录。
* 用 `--editor URL --instance ID`，或环境变量 `SCA_EDITOR_URL` 与 `SCA_EDITOR_INSTANCE`（两个都要）指定其中一个，适用于任何 `sca cell`、
  `sca feature`、`sca sketch`、`sca new` 命令。被指定的编辑器无论命令在哪里运行都会被使用，并核对实例 id；绝不会退回去读文件。
* `sca cell`、`sca feature`、`sca sketch` 的报告会写明是哪个编辑器回答的：`editor: {url, workspace, instance}`。
* `sca snapshot` 和 `sca viewport` 仍然读按 workspace 存放的文件，同一 workspace 上的两个编辑器会在这里互相覆盖。

## `sca edit` 自己选端口

`--port` 现在默认是 `0`：由系统选一个空闲端口，编辑器就在它自己 bind 的 socket 上提供服务，中间没有别的进程能抢走端口。开始监听后，
标准输出会有一行：

```
SCA_EDITOR_READY {"url": "http://127.0.0.1:41233", "instance": "3f9c2a7d41b0", "workspace": "/work/proj", "pid": 812}
```

`--port N` 仍然是固定端口，被占用时会报错。原来的默认值是 7180。
