# 2.3.0 更新说明

`sca edit` 编辑器和 agent 现在可以同时处理同一个 notebook，互不覆盖。

## 编辑器会接收对文件的修改

以前编辑器把打开的 notebook 放在内存里，每次编辑都重写文件，agent 保存的修改会被编辑器的下一次保存
覆盖，也不会显示出来。现在编辑器会监视文件：保存后的修改会与编辑器里的 cell 对比，按 cell 逐个应用。
变化的 cell 会更新并重新运行，新增或删除的 cell 会出现或消失，页面不会刷新或闪烁。setup cell 或
`@app.function` cell 的修改会重启 kernel；无法解析的文件会被忽略，直到下一次可解析的保存。

如果同一个 cell 两边都改了，**保留文件里的版本**，你还没保存的文字会记在底部日志里。工作区里新增或删除的
notebook 会自动出现在列表中。

## `sca cell` 和 `sca new`

```bash
sca cell ls [--code]                 # 带编号的 cell，含状态、错误和输出
sca cell get 3
echo 'L = 90' | sca cell put 3       # 替换 cell 代码并运行
sca cell insert --after 3 -f new.py
sca cell rm 4
sca cell run [CELL ...]
sca new bracket --kind part          # 新建 notebook，运行中的编辑器会列出它
```

这些命令通过运行中的编辑器工作（由 `<workspace>/.sca-editor/server.json` 找到）：页面实时显示修改，每次写入
都会打印被改 cell 的状态、错误和输出。没有运行中的编辑器，或编辑器打开的是别的 notebook 时，`ls` 和 `get`
读取文件，写命令会拒绝：这时直接编辑文件即可。

skill（`editor-collaboration`）和 `landing.md` 已让 agent 按这种方式工作。
