# 2.3.0 更新说明

2.3.0 接在 2.2.7 之后。2.2.8 已被撤回（PyPI 上已 yank，GitHub 上的发布也已删除），取代它的 2.2.9 已经准备好但从未发布，
所以两者的全部内容都在 2.3.0 里。这是一个次版本：它移除了被撤回的 2.2.8 里的接口，增加了关键字，并改变了
`cut_rsolid` 和 `intersect_rsolid` 默认返回的结果。

## Part 只持有一个实体

2.2.8 让一个 `Part` 可以持有多个 body，而这样的 Part 没法参与装配。2.3.0 让 Part 重新只持有一个实体，同时保留编辑器需要的能力：
建模过程中，笔记本里可以并排放着几个实体。

编辑器必须允许一个笔记本里同时存在几个实体，而且它们之间不需要装配约束：比如先阵列刀具再切割，总有一刻刀具有好几把，
本体也在。2.2.8 把这件事放进了 Part 里解决。但是 Part 是装配里被摆放、被配合、被挂接口的单位，而持有多个 body 的 Part 这些都做不到：

* 它不能带连接器，所以任何配合或公开连接器都够不到它；
* 装配里只要有一个这样的 Part，`explode_rassembly` 就报 `TypeError`；
* 旧的场景编译器有四处直接读 Part 的唯一 body。

并排的几个实体只是笔记本里的中间值，不是产品里的零件。所以现在它们是笔记本里的普通值，Part 就是一个实体。完整的说明在
`design-docs/part-holds-one-solid.md`。

* **`make_part_rpart(part_id, body, name=None)`** 接受一个实体、一个 `Body`（带显示名、颜色和不透明度的实体），或者切割分裂后
  恰好只有一块的列表。给多个实体会报 `ValueError`，并说明该怎么做：每个实体做成一个 Part 放进装配（只是放在一起时用单位位姿），
  或者先把它们合并、切割成一个实体。
* **已移除**（它们只在被撤回的 2.2.8 里存在过）：`bodies=` 参数、`Part.multi_body`、`scad.part_shape`、
  `inspect_body_overlaps_rlist`、`BodyOverlap`、`BodyOverlapWarning`，以及零件定义的 `simplecad-part-definition-3` 版式和
  `solid_cache.bodies`。记录了“一个 Part 里有多个实体”的模型 JSON，重放时会被拒绝，并给出同样的提示。
* **零件笔记本里只有一个开放实体**时，仍然自动得到隐式 Part。**有多个开放实体**时没有产品：运行会报 `SeveralOpenBodiesError`，
  并列出这些实体；请用真正作为零件的那个来做 Part（`scad.make_part_rpart(part_id=scad.notebook_id(), body=...)`），或者给每个
  实体各做一个 Part，再放进装配。
* **编辑器**会把这些开放实体并排画出来，标题栏显示“N 个开放实体”；`use_as_product` 会用你选的那个实体做出 Part。

## 布尔运算：`cut_rsolid` 和 `intersect_rsolid` 会清理结果

`union_rsolid` 一直会把落在同一个曲面上的面和边合并；`cut_rsolid`、`cut_rsolid_list` 和 `intersect_rsolid` 以前不会。
用圆柱从侧面切穿一个盒子，圆柱壁会沿着它的参数接缝被劈成两个面，而 OCCT 对沿着这种被劈开的面的边做圆角是错的：
它会返回体积不对的无效实体而且不报错（issue #88），或者拒绝，并把原因怪到半径上。

* **`cut_rsolid`、`cut_rsolid_list`、`intersect_rsolid` 增加 `clean=True`**（默认），把留下的被劈开的面和边合并。标签和血缘跟着
  清理走。如果合并后的结果无效，就保留原始结果。`clean=False` 和以前一样返回原始结果。
* **结果的面和边变少**：以前会留下被劈开的面的切割，几何（体积、面积、包围盒）不变，但拓扑变了，因此这种实体的指纹也变了。
  包含这种切割的、已保存的产品需要重新生成。
* **`fillet_rsolid` 和 `chamfer_rsolid` 会检查结果**：输入有效而 OCCT 判定结果无效时，会报出指明操作的错误，而不是把它当返回值交出去。
* **圆角因面被劈开而失败时会直说**（并说明半径不是限制），不再建议更小的半径。
* **记录的操作图**：`clean` 是 `make_cut_rsolid`、`make_cut_rsolid_list` 和 `make_intersect_rsolid` 的记录参数。2.3.0 之前记录的
  图没有这个参数，重放时会和缺少任何参数的图一样被拒绝：请重新记录。

## 不经过 `.scadpkg` 文件直接导出，以及在源目录只读时运行

* **导出器接受构建的结果。** `export_product_package_to_step / stl / obj / mjcf` 和 FreeCAD 转换器除了包、字节和路径，也接受
  `@scad.part` / `@scad.assemble` 的结果（或它的定义），在内存里打包，且不生成场景（没有导出器会读那份网格投影）。
  从刚建好的零件导出 STEP：`scad.exporter.export_product_package_to_step(build_part(), "part.step")`；issue #89 里那块
  120 x 120 x 10 的板，先 capture 再导出要 1.85 秒，现在 0.26 秒。
* **`run_notebook(path, cache=False)` 不碰源目录。** 它不再写 `__marimo__/.../deps.json`，也不在笔记本旁边创建状态目录，所以能在
  源目录只读的环境里运行（比如源码以 `:ro` 挂载的容器）。带缓存的运行仍然把状态写在那里，写不进就报错。
* **单脚本任务是受支持的入口。** 技能里“模型是 marimo 笔记本”（R3）仍然适用于人会打开或复用的一切，现在也允许任务明确要求单个脚本时
  使用普通脚本，模板在 `domains/export-and-translation.md`。

## 指纹不会把落在量化边界上的值劈开

实体的几何指纹把每个测量值量化到 1e-7 mm。像 -3.34690815 mm 这样的设计值恰好落在这个取整的边界上，计算噪声（比如 BREP 往返）
差一个末位，就会被取整到相邻的整数，于是指纹变了，恢复拓扑快照时报 `geometry_mismatch`（issue #87）。现在量化器在取整前，
先把值吸附到一个比噪声粗得多、比量化单位细得多的网格上。带有边界上的值的实体，其指纹会变化一次；在此之前记录的快照无法恢复，
需要重新捕获。

## 修复

* 在 Windows 上，`sca cell` 不会再杀掉它正在对话的编辑器：现在探测编辑器进程时不再发信号（Windows 上
  `os.kill(pid, 0)` 会直接终止进程）。
* 从源码构建：GCC 14（`operators_promote.cpp` 补上 `<algorithm>`）、MinGW（定义 `_USE_MATH_DEFINES`，以及编译器是 MinGW 的
  `g++` 时 `build_occt.py` 选用 Ninja）；macOS 的安装包改在 `macos-15` 上构建（安装包仍然面向 macOS 14.0）。

## 给贡献者

* **在 Windows 上，直接 `uv sync` 就能构建。** 没有 Visual Studio 时，构建以前会落到 NMake 生成器而失败，每个贡献者都得手动设
  `CMAKE_GENERATOR`、`CC`、`CXX` 和 `CMAKE_ARGS`。现在构建后端（`tools/build_backend/scad_build.py`）在没有 Visual Studio 时选用
  Ninja 和 PATH 上的 gcc，自己找 OpenCASCADE（`SCAD_OCCT_PREFIX`、`C:/occt`，或者它一次性构建的用户缓存目录），并按内存限制并行数。
  你自己设的值仍然优先。`uv` 只在 `src/cpp` 变化时才重新构建（`[tool.uv] cache-keys`），改版本号不会触发。
* `AGENT.md` 记录了在 Windows 上如何重新编译 C++ 模块，以及提交该怎么组织：一个决策一个提交，说明里写清楚促成这个决策的讨论和原因。
